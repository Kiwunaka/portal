# Portal Roadmap (2026-02)

## Current baseline

- Free policy:
  - `FREE_LIMIT_IP=2`
  - `FREE_TOTAL_GB=40`
- Paid policy:
  - `PAID_LIMIT_IP=5`
  - unlimited traffic
- Support contact is configurable via `SUPPORT_USERNAME`.

## Next implementation waves

1. Support tickets (operator workflow)
- Add ticket entity (`open/in_progress/closed`) with message thread history.
- Add user-side actions: `Create ticket`, `My tickets`, `Reply`.
- Add operator-side actions: queue, claim, reply, close, SLA labels.
- Optional: bridge to dedicated support bot/webhook.
 - Status: phase 1 implemented in `portal_bot/bot.py` + `portal_bot/tickets_repo.py`.

2. WebApp parity with bot
- Mirror key actions from bot: tariff selection, key copy, support ticket creation, diagnostics.
- Add deep links for clients per platform.
- Expose plan limits in account card (devices + traffic cap).

3. Node/network hardening
- Add node diagnostics scripts:
  - DNS behavior check per node.
  - Reality/SNI consistency checks against expected country profile.
- Add runbook for periodic checks and rollback.
- Keep Free speed policy explicit:
  - aggregate limiter (`tc`) and optional per-IP limiter (`nftables`), with clear caveats.

4. Capacity and balancing
- Introduce assignment policy:
  - pick target node by active users + recent load.
  - keep manual override for incidents.
- Add observability for node saturation and reassignment triggers.

5. Remnawave migration decision gate
- Run a pilot on a separate environment (do not switch production first).
- Compare:
  - operational complexity,
  - required integrations (payments, support flows, WebApp),
  - migration risks and rollback cost.
