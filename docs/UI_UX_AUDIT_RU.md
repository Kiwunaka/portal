# UI/UX аудит WebApp и маркетинг-сайта

Дата: 2026-03-07

## Что проверено

- Живые страницы маркетинга: `/`, `/offer/`, `/privacy/`, `/checkout/`
- Живые страницы WebApp: `/webapp/`, `/webapp/dashboard/`, `/webapp/pricing/`, `/webapp/support/`, `/webapp/admin/`
- Исходники маркетинга и WebApp
- Согласованность между copy-layer, CTA, входом через Telegram и экраном оплаты

## Что было найдено

1. На маркетинговой главной часть CTA визуально и логически конфликтовала с bot-first сценарием.
2. На legal-страницах сильный CTA вёл в `/checkout/`, где без персонального тикета пользователь попадал в тупиковый disabled-flow.
3. На публичном checkout заголовок и empty-state выглядели как технический экран, а не как управляемый переход.
4. В WebApp entry-экране кнопка `Открыть кабинет` показывалась даже тогда, когда браузерная сессия ещё не подтверждена.
5. QR-код в кабинете подтягивался через внешний сервис, что добавляло сетевую хрупкость и лишнюю зависимость.
6. Copy-каталог маркетинга содержал подписи CTA, которые не совпадали с фактическими маршрутами.

## Что исправлено

- Маркетинговый hero оставлен bot-first:
  - primary CTA ведёт в Telegram;
  - secondary CTA ведёт к блоку планов;
  - ссылка на кабинет теперь явно адресована уже активным пользователям.
- Legal-страницы теперь ведут в Telegram, а не в тупиковый public checkout.
- Public checkout без `checkout_ticket` теперь работает как нормальный gateway:
  - объясняет, что нужен персональный сценарий;
  - ведёт в Telegram или в кабинет;
  - не выглядит как сломанная форма оплаты.
- Входной экран WebApp больше не обещает “Открыть кабинет”, если пользователь ещё не прошёл браузерный вход через Telegram.
- Pricing в WebApp больше не обещает “сразу оплату без промежуточных шагов”, если впереди ещё есть вход через Telegram.
- Dashboard для активного пользователя теперь ставит выше действия “скачать приложения / скопировать ссылку / открыть QR”, а не только продление.
- Сравнение планов в кабинете теперь показывает реальные точки подключения:
  - `Start` -> `NL`
  - `Pro/Ultra` -> `IT, NL, PL, US`
- Checkout в кабинете и на маркетинговом gateway объясняет реальный следующий шаг без внутреннего продукта/техжаргона.
- QR-код подписки теперь генерируется локально в WebApp через библиотеку `qrcode`.
- Copy-каталог и живые CTA приведены к одному смыслу.
- В bot-flow убраны прямые публичные упоминания `VPN` из paywall и выбора тарифа.

## Проверка после правок

- Сборка `marketing` должна проходить без ошибок.
- Сборка `webapp` должна проходить без ошибок.
- Главный путь первого входа: marketing -> Telegram -> WebApp не должен содержать misleading CTA.
- Legal-страницы не должны вести в нерабочий сценарий.
- WebApp entry без web-сессии должен показывать только релевантные действия.
- Dashboard должен показывать QR-код без обращения к внешнему `qrserver`.

## Остаточные замечания

- На маркетинге ссылка на кабинет оставлена в навигации и support-блоке для уже активных пользователей. Это допустимо, пока primary cold-flow остаётся bot-first.
- Следующий уровень улучшений уже не критичный: тонкая типографика, микрокопирайт и более глубокая унификация состояний между marketing checkout и WebApp checkout.
- Локальные Windows-сборки могут спотыкаться о lock на каталог `out`; для релизной проверки стоит опираться на clean deploy-stage, а не на reuse локального export-каталога.
