## Status Rules

- `Retest passed` means the story has a recorded local automated verification loop or retained imported pass evidence now mapped to direct test files.
- `Manual owner test` means local code checks exist but a physical device, real session, provider dashboard, live deploy, or owner account remains outside local automation.
- Every `Manual owner test` canonical row must have at least one row in `pokrov-owner-gated-scenarios.csv`, and every owner-gated scenario row must point back to a canonical row that is still `Manual owner test`.
- `Needs scenario test` means an active backend route, script/operator workflow, or other entrypoint has no direct automated scenario-test reference yet. Current `Needs scenario test` rows are script/operator workflows imported from `scripts/manifest.yaml`; the current count is `0`.
- `Needs story mapping review` in the entrypoint story coverage audit means a source entrypoint could not be linked to route/story/script evidence. Current count is `0`.
- Canonical tracker status fields are normalized by `tests/test_story_test_evidence_audit.py`: every row must use `Retest passed` or `Manual owner test`; `latest_result`, `fix_status`, `retest_status`, and `next_action` must be non-empty; `Retest passed` rows must not keep stale fail/issue text in `latest_result`.
- Canonical `source_tracker` values must either resolve to an existing workbook/path or use one of the generated labels backed by current source: `generated from portal_bot/api.py route decorators` or `generated from scripts/manifest.yaml`.
- Live/provider/device/RU checks must be labelled explicitly as `PASS`, `FAIL`, `BLOCKED_BY_ACCESS`, `SKIPPED_BY_OWNER`, `OPERATOR_ATTESTED`, `NOT_REQUESTED`, or `NOT_APPLICABLE`; do not infer them from local static tests.
