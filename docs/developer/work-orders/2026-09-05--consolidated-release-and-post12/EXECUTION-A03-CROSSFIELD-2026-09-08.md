The negative regression first reproduced six accepted invalid combinations:
overlapping H ranges, oversized S1, oversized S4, S4 plus MTU above the supported
buffer, rekey range extending beyond rejection, and zero receive-refresh time.
A stopped isolated upstream userspace device independently confirmed that the
pinned UAPI rejects H overlap but accepts oversized S4 and inverted timers.
That fixture makes no Up call or network request. No runtime crash was induced
or claimed; this establishes the missing local validation boundary.

The correction rejects those combinations before device creation. H1-H4 must
be disjoint uint32 ranges. S1+148, S2+92, S3+64, S4+MTU+32 and Jmax must fit
2016 bytes, the pinned Windows buffer (`2048-32`) shared as the managed
Android/Windows ceiling. A smaller target buffer narrows the ceiling further.
Exact-boundary acceptance and one-byte-over rejection run for both contracts.
AWG3.1 latest send-rekey precedes earliest rejection, and the upstream
receive-refresh formula stays positive using its minimum keepalive/retry
values. Omitted fields retain pinned defaults 120/180/10/5 seconds.

Existing I/J and header-protection checks remain: at most 512 generated bytes
per instruction packet, bounded supported tags, no IPC control characters,
AWG3.1 Jmax <=1279, exactly 32 HP key bytes and S1-S4 >=12. HP-off, MTU 1360/1420
and unsupported fields are not positive cases. Upstream content padding caps
at the inner MTU; managed buffer checks do not promise a whole-path MTU,
throughput, optimal preset, independent origin or device route proof.

Both AWG labs passed authenticated TLS/HTTP on the owned Pi with MTU
1280/1400/1408 after the fix. Each used the exact source snapshot, a separate
userspace device and a 4096-byte inert request header. Strict SSH trust and
direct-default-route preflight passed; temporary remote state was removed.
