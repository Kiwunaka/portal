# Payments Callback Runbook (Freekassa Dual Shop)

Updated: `2026-02-14`

## 1. Architecture

- Domains:
  - `portal-privacy.online`: marketing and checkout UI.
  - `kiwunaka.space`: API, callbacks, `pay/success`, `pay/fail`.
- Freekassa shops:
  - `site` shop for website checkout.
  - `bot` shop for payments started from bot UI.
- Shop selection is controlled by request `source` (`site|bot`) and mapped to `FK_SITE_*` / `FK_BOT_*`.

## 2. Endpoint Matrix

### Redirect pages

- `GET|POST /pay/success`
- `GET|POST /pay/fail`

### Freekassa orchestration

- `POST /api/payments/freekassa/orders/create`
- `GET /api/payments/freekassa/orders/{order_id}`
- `POST /api/payments/freekassa/orders/{order_id}/refund`
- `GET /api/payments/freekassa/currencies`
- `GET /api/payments/freekassa/currencies/{currency}/status`

### Callback

- `POST|GET /api/payments/freekassa/notify`
  - successful signed `POST` returns plain text `YES`;
  - invalid signature returns `400`;
  - IP outside allowlist returns `403`.

## 3. Signature Rules

### SCI notify signature

Freekassa callback signature:

`md5(MERCHANT_ID:AMOUNT:SECRET_WORD_2:MERCHANT_ORDER_ID)`

Validated against callback fields:
- `MERCHANT_ID`
- `AMOUNT`
- `MERCHANT_ORDER_ID`
- `SIGN`

### API request signature

Freekassa API signature is generated by `HMAC-SHA256` over canonical payload:
- include top-level keys: `data`, `iat`, `nonce`, `shopId`;
- flatten values and join using `|`;
- sign using `FK_*_API_KEY`.

## 4. Idempotency and Access Activation

1. Every callback is persisted into `external_payment_events`.
2. Deduplication key: (`provider`, `event_type`, `external_id`).
3. `external_orders` is updated by upsert.
4. First valid `result` event performs activation:
   - set `sub_type=PAID`;
   - set `current_plan_code`;
   - extend `expiry_at`;
   - trigger node sync.
5. Duplicate notify does not activate twice (`duplicate=true`).

## 5. Required Environment Variables

- Feature flags:
  - `RUB_CHECKOUT_ENABLED`
  - `BOT_RUB_BUTTON_ENABLED`
  - `CHECKOUT_WIDGET_ENABLED`
  - `CHANNEL_SPEED_BUMP_ENABLED`
- Freekassa site:
  - `FK_SITE_SHOP_ID`
  - `FK_SITE_API_KEY`
  - `FK_SITE_SECRET_WORD_1`
  - `FK_SITE_SECRET_WORD_2`
- Freekassa bot:
  - `FK_BOT_SHOP_ID`
  - `FK_BOT_API_KEY`
  - `FK_BOT_SECRET_WORD_1`
  - `FK_BOT_SECRET_WORD_2`
- Network policy:
  - `FK_NOTIFY_IP_ALLOWLIST` (comma-separated IP/CIDR list)
- URLs:
  - `PUBLIC_API_BASE_URL`
  - `PAY_SUCCESS_URL`
  - `PAY_FAIL_URL`

Secrets must be stored only in server env/secret manager, never in git.

## 6. Smoke Checks

1. `GET /api/health` returns `200`.
2. `GET /pay/success` returns `200`.
3. `GET /pay/fail` returns `200`.
4. Authenticated `POST /api/payments/freekassa/orders/create` returns `ok=true`.
5. Signed `POST /api/payments/freekassa/notify` returns `YES`.
6. Replayed notify returns `duplicate=true`.
7. User state updated:
   - `sub_type=PAID`;
   - `current_plan_code` matches order;
   - `expiry_at` moved forward.
8. Node sync and subscription visibility are healthy in bot/WebApp.

## 7. Rollout

1. Deploy backend with flags OFF.
2. Enable `RUB_CHECKOUT_ENABLED=true` for internal group.
3. Enable `BOT_RUB_BUTTON_ENABLED=true`.
4. Enable `CHECKOUT_WIDGET_ENABLED=true`.
5. Enable `CHANNEL_SPEED_BUMP_ENABLED=true` after funnel verification.

## 8. Rollback

1. Set flags OFF:
   - `RUB_CHECKOUT_ENABLED=false`
   - `BOT_RUB_BUTTON_ENABLED=false`
   - `CHECKOUT_WIDGET_ENABLED=false`
   - `CHANNEL_SPEED_BUMP_ENABLED=false`
2. Restart `portal-api` and `portal-bot`.
3. Validate Stars-only flow.
4. No DB rollback is required (schema is backward-compatible).
