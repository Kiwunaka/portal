# Передача для Production-подписи Android

Last updated: 2026-04-15

## Зачем нужен этот файл

Используйте эту инструкцию, когда Android уже почти готов, но публичный релиз всё ещё заблокирован из-за production-подписи.

Этот файл только про подпись релизной сборки. Он не заменяет проверку на реальном Android-устройстве.

## Когда сразу останавливаемся

Сразу пишем, что релиз заблокирован, если нет хотя бы одного пункта:

- боевого keystore или содержимого ключа подписи
- `ANDROID_SIGNING_STORE_PASSWORD`
- `ANDROID_SIGNING_KEY_PASSWORD`
- `ANDROID_SIGNING_KEY_ALIAS`
- понимания, к какому релизу относится эта подпись: тег, версия или кандидат на публикацию

Отладочный keystore для публичного Android-релиза использовать нельзя.

## Что нужно получить от вас

Передайте это не через git и не в markdown:

- `ANDROID_SIGNING_KEY`
- `ANDROID_SIGNING_STORE_PASSWORD`
- `ANDROID_SIGNING_KEY_PASSWORD`
- `ANDROID_SIGNING_KEY_ALIAS`
- номер версии или тег релиза, для которого подписываем сборку
- подтверждение, что это именно боевой production-ключ, а не временный тестовый

Если у вас используется локальный файл `android/key.properties`, а не прямые переменные окружения, нужно ещё:

- прислать безопасный локальный путь к этому файлу
- отдельно подтвердить, что файл указывает именно на боевой keystore

## Что делать по шагам

1. Убедитесь, что основной набор проверок по репозиторию уже зелёный.
2. Убедитесь, что Android всё ещё считается заблокированным до тех пор, пока не будут закрыты и подпись, и physical-device audit.
3. Из корня репозитория соберите релизные Android-артефакты:

```powershell
python scripts/run_client_release_gate.py build --target android-apk
python scripts/run_client_release_gate.py build --target android-aab
```

4. Подложите production-секреты через согласованный локальный способ.
5. Если до этого сборка делалась с fallback на debug keystore, пересоберите её заново уже с боевой подписью.
6. Проверьте, что итоговые файлы соответствуют каноническим именам:
   - `pokrov-android-universal.apk`
   - `pokrov-android-market.aab`
7. Подготовьте артефакты к публикации:
   - `APK` для прямой раздачи
   - `AAB` для Google Play

## Что нужно прислать мне обратно

Пришлите простым списком:

- кто именно выполнял подпись
- дата и время подписи
- какой тег или версия были подписаны
- точные имена итоговых файлов
- какие команды запускались
- подтверждение, что использовался production-ключ, но без самих секретов
- куда загружены подписанные `APK` и `AAB`

Подойдут такие доказательства:

- лог сборки, где видно, что релизная подпись прошла успешно
- подтверждение загрузки `AAB` в Play Console
- ссылка на GitHub Release или другое место, где лежит финальный `APK`

## Частые причины блокировки

- есть только debug keystore
- пароль, alias или ключ не подходят к production-keystore
- локально всё собрано, но это не финальный релизный кандидат
- подписанные файлы есть, но никуда не выложены
- не закрыт physical-device localhost audit

## Когда считаем задачу закрытой

Android всё ещё считается заблокированным, пока не выполнены все пункты:

- production-подпись готова
- audit на реальном Android-устройстве пройден
- релизные ссылки опубликованы
- в финальном handoff явно написано либо "готово", либо "заблокировано", с точной причиной
