- `release_gate_check.py --quick --brain-ip` PASS proves brain runtime/static verify and node predeploy readiness for the selected quick gate. - `scripts/verify_brain_ready.py` PASS proves service/listener/public-surface/subscription health and removed legacy FreeKassa static absence. It does not prove app artifact publication, paid checkout readiness, live email inbox delivery, RU-origin reachability, or Android device safety.
- Local APK/EXE hashes prove build artifact identity only. They do not prove GitHub Release publication, download reachability, Android physical safety, or trusted Windows signing; unsigned Windows beta risk is accepted only as an explicit outside-store beta caveat.
- `staged-client-apps-2026-05-07.json` and `--policy-only` smoke prove URL shape only. They do not prove the GitHub assets exist or that live `/api/client/apps` returns the final runtime links.
- `prepare_github_release_plan.py` and `publish_github_release_assets.py` dry-runs prove the planned asset names and safety guards only. The staged GitHub prerelease proves asset upload and URL reachability, but it does not prove runtime `APP_*` sync, live `/api/client/apps` response, paid checkout readiness, email delivery proof, or public launch authorization.
- `public_beta_launch_decision.py` summarizes the latest evidence into one JSON verdict. It can make the NO-GO harder to misread, but it does not replace any missing runtime download, payment, email, public handoff, RU-origin, or Windows signed-installer evidence.
- `/api/payments/providers` returning `blocked=true` is correct NO-GO evidence, not a paid-checkout launch. Lava.top checkout can be called public only after the aggregate paid-checkout evidence is green.
- Admin release cockpit PASS means the operator can see the gate state. It does not publish, sync runtime links, run external probes, or convert blocked dependencies into GO evidence.
