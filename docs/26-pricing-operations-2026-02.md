# Pricing Operations (RUB/Stars) 2026-02

Обновлено: `2026-02-15`

> Исторический снимок.
> Ниже встречаются старые названия `Pro / Ultra`. Для текущей операционной работы используйте фактическую лестницу:
> `Приветственный 30 дней`, `1 месяц`, `3 месяца`, `6 месяцев`, `9 месяцев`, `12 месяцев`.

## 1) Назначение

Документ для операционного управления ценами:
- входные допущения;
- формула экономики;
- диапазон маржинальности;
- правила изменения цен в админке.

## 2) Входные допущения

Параметры на 1 оплаченный заказ:

- `P` — цена плана (RUB).
- `f` — переменная комиссия провайдера (доля), пример `0.10`.
- `c_fix` — фикс-комиссия провайдера (RUB), если есть.
- `d` — средняя скидка (доля), учитывая промо и бонусы.
- `S` — инфраструктурная себестоимость на период плана.
- `A` — стоимость привлечения/промо (если учитывается).
- `R` — резерв на возвраты/споры.

## 3) Формула

Net revenue:

`net = P * (1 - f) - c_fix - (P * d)`

Contribution margin:

`cm = net - S - A - R`

Условие устойчивости:

`cm >= 0`

Для `Start 99`:

`S_max = P * (1 - f) - c_fix - (P * d) - A - R`

Если `S > S_max`, компенсируем апселлом или корректируем параметры оффера.

## 4) Ориентиры маржинальности

Рабочие пороги:
- `cm < 0`: красная зона, требуется немедленная коррекция.
- `0 <= cm < 15% P`: жёлтая зона, мониторинг ежедневно.
- `cm >= 15% P`: зелёная зона, допустимый запас.

Рекомендуемый целевой диапазон:
- `15–30%` contribution margin на среднем чеке.

## 5) Правила изменения цены

1. Менять цену только через `plan_catalog` (админка `Планы`).
2. За один цикл менять не более одного фактора:
   - либо `amount_rub`,
   - либо `days/device_limit/node_policy`.
3. После изменения выдержать минимум 72 часа до следующей правки.
4. Для `start_99` сначала корректировать ограничения/скидки, и только потом headline price.
5. Любое изменение фиксировать в changelog кампании.

## 6) Start 99 Policy

Текущая политика:
- `99 RUB`
- `30 days`
- `1 device`
- `NL-only`

Если нужно улучшить экономику, порядок действий:
1. сократить глубину discount-кампаний;
2. ограничить охват промо-кодов;
3. усилить апселл на более длинные сроки `3 / 6 / 9 / 12 месяцев`;
4. только после этого пересматривать цену.

## 7) Weekly Review Checklist

1. Конверсия `Start -> Paid+`.
2. Доля заказов со скидкой.
3. Средний `cm` по планам.
4. Доля возвратов/споров.
5. Нагрузка по регионам и фактическая `S`.

## 8) Stars как вторичный канал

- Stars остаются резервным способом.
- Цена в Stars должна синхронизироваться с RUB-матрицей и текущими промо-правилами.
- При сильном расхождении курсового эквивалента корректируется `amount_stars` в `plan_catalog`.
